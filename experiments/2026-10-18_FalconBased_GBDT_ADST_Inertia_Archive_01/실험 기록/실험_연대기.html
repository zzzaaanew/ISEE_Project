최신 보고서의 성능 우위 주장에 필요한 정정

  1. 미래 label이 학습에 들어가는 경로: unified final train과 exact scratch는 sample_indices(train_start, origin_bin)을 사용한다. sample_indices는 gt_matrix를 그대로 자르고, gt_matrix는 각 onset의 직전24시간을 양성으로 만든다. 따라서 origin 직전 학습 행의 label에 origin 이후 test-period onset이 들어갈 수 있다. validation도 origin까지 사용하고 train/validation purge가 없다. base에 PURGE_NS 상수가 있어도 이 실행 경로에는 적용되지 않는다. 10분 feature buffer는 24시간 label 성숙을 보장하지 않는다. 최신 수치 상승 중 누출 영향의 크기는 미측정이다.
  2. 새 Falcon 코드와 benchmark 호출 경로가 다르다. exact scratch는 UnifiedADSTPipeline.extract_enhanced_branch1_features를 사용한다. 이 경로는 기존30개 통계+cross7+node8=45개이며 peer zscore/rank/persistence를 만들지 않는다. 새 EnhancedTelemetryEngine은 base22+cross7+topology8+peer5+temporal3=45개다. 최신 수치0.0512를 새 Falcon 특징 효과로 귀속할 증거가 없다.

  • 새 topology/peer 구현은 n개 sample마다 전체1,992GPU 열을 복사한 뒤 같은 노드8개만 꺼낸다. 필요한8개 GPU를 직접 gather하면 이 임시 배열 크기는249분의1이다. 예시300,000 sample에서 float32 배열은 metric당2.3904GB→9.6MB다. 실행 시간 개선은 아직 미측정이다. chunk 처리 후 GPU window/peer reduction을 비교한다.
  • contiguous8 GPU 정렬을 물리 노드로 가정한다. 실제 node ID 매핑을 확인하거나 가정으로 명시해야 peer 특징 해석이 가능하다. 이 코드는 학습형 GNN이 아니라 정적 노드 통계다.
  • thermal_headroom/power_headroom은 base delta를 반복하고 고정1h에서 slope도 delta와 같다. thermal_persistence는 (last−mean)/std이며 보고서의 임계온도 초과 지속시간이 아니다. 특징 정의·중복·결측 처리를 정정하고 manifest에 기록한다.
