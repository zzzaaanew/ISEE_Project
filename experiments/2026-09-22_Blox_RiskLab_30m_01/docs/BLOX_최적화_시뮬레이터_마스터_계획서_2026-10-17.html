1. 기존 Blox 연동 보고서 5종 진단 및 실측 워크로드 편중성 근거

  • 병목 ① (고정 임계값 마스킹의 100% 기아 현상): 준호의 risk_mask_packed(99% 재현율 임계값 τ=0.002975)는 가용 GPU 부족을 유발하여 16,560개 작업 중 완료 작업 0개(100% Starvation)로 귀결됨.
  • 병목 ② (작업 크기·길이를 무시한 단일 작업 순차 Greedy DP): 기존 risk_prefer_packed는 한 번에 작업 1개만 보고 배치하며, 1-GPU 단기 작업과 8-GPU 장기 분산 학습(Gang-Scheduling) 작업을 동일 가중치로 취급함.
  • 병목 ③ (과도한 LAS 선점 폭풍 방치): 매 300초마다 근소한 서비스 시간 차이로 대형 작업을 강제 선점하여, 선점 오버헤드(2,880,000s)가 장애 손실(1,020s)의 2,800배에 달함.
  • 실측 워크로드 편중성 검증 (job_trace.parquet, 16,560개 작업): 작업 수 기준으로는 1-GPU 작업이 75.04%이나, 클러스터 총 GPU-Hours의 84.2%는 8-GPU 이상 대형 Gang-Job이 소비하며 상위 10% 장기 작업이 전체 GPU-Hours의 91.90%를 점유함. 즉, 대형·장기 Gang-Job의 취약도(Vj)에 비례해 저위험 서버를 우선 배정하는 다중 작업 공최적화(Co-Optimization)가 필수적임.

2. 양대 해법(해법 A & 해법 B) 및 수리모형·메타휴리스틱 설계

2.1 [해법 A] ML 재학습 없는 Dual-Branch 실효 위험도 + 작업 취약도(Vj) + 예산 제약형 Top-K 격리

• Dual-Branch 실효 위험도: ri,teff = pi,t(fuse) + 0.25 · pi,t(B1) · I(pi,t(B2) > Q0.75(pt(B2)))
• 작업 취약도 가중치: Vj = ωj · gj1.25 · (Drec + min(Ickpt, uj + ΔH)) · (1 + min(rj, 4ΔH) / ΔH)
• 다중 작업 배치 목적함수 (BILP): min Σj,s αpack yj,s + Σj,i βrisk Vj ri,teff xj,i + Σj γhot Vj maxi:xj,i=1 ri,teff
  • Warm-Start 2-Opt + Simulated Annealing 메타휴리스틱 (metaheuristic_packed): 취약도 내림차순 Exact DP로 초기해(Warm-Start)를 생성한 후, 서버 단편화(Σ yj,s)를 악화시키지 않는 제약 하에 다중 작업 간 및 유휴 GPU 간 2-Opt Swap 국소 탐색과 SA를 수행하여 전역 위험 노출을 최소화함.
  • 비용-편익 선점 가드 (full_co_optimized): 서비스 시간 마진(Δmargin = 300s), 완료 임박 작업 보호(잔여시간 rp ≤ 180s 선점 금지), Best-Fit 희생양 선택을 결합하여 불필요한 선점 낭비를 25.6% 제거함.

2.2 [해법 B] NVIDIA 공식 문서 기반 XID 31(하드웨어 결함) vs XID 43(소프트 리셋) 충격량 이원화

  • Hard Fault (XID 31/48/63/64/74/79): MMU/하드웨어 페이지 결함이므로 작업 즉시 중단 및 recovery_end까지 장기 노드 격리 적용.
  • Soft Fault (XID 43 단독): 사용자 앱/컨텍스트 종료 이벤트이므로 확률 ρ43 ∈ {0.5, 1.0}로 작업을 중단하되, 수 시간의 하드웨어 격리 대신 60초 소프트 컨텍스트 리셋(soft_xid_reset_seconds)만 부과 후 즉시 클러스터에 복귀.
